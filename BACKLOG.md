## Active

- **GitHub Packages publish** — the attempt during 0.1 got 403 because the ambient `GITHUB_TOKEN` lacks `write:packages`. Maven Central is doing the heavy lifting so this is a belt-and-braces extra, but still nominally open if we want the mirror.

- **`JavaTransformsClasspathGated` only gates the annotation-add, not the call conversions** — surfaced by `ClasspathGateIntegrationTest`. In a Lombok-less module the composition still rewrites `System.out.println(...)` to `log.info(...)` even though `@Slf4j` (which would define `log`) is correctly skipped. Result: uncompilable Java. Either gate `SystemOutToSlf4j` / `PrintStackTraceToLog` / `JulToSlf4j` on the same classpath check, or short-circuit the whole composition when Lombok is absent. The `MigrateToSlf4jRecipeNoDeps` and `SystemOutToSlf4jRecipeNoDeps` users are the affected population — the recipe docstrings tell them they are responsible for adding Lombok themselves, but if they don't, the recipe corrupts their source rather than no-op'ing.

- **Expand integration coverage further** — currently covered: `AddLombokDependency` (inline + catalog), `AddSlf4jDependencies` (dedup-ordering regression guard), `MigrateToSlf4jRecipe` (mixed-pattern end-to-end including XML seeding), `AddLombokSlf4jAnnotation` classpath-gate negative case. Still bootstrap-only: `SystemOutToSlf4jRecipe` (likely covered transitively by `MigrateToSlf4jRecipe`); multi-module / `includeBuild` shapes (the harness only models a single `forProjectDirectory`).

- **Re-enable Java 25 in integration tests** — model `8.81.2` added an `isGradle9OrLater(version)` check that gates the removed `-b` flag, so JDK 25 + Gradle 9 *almost* works. Tried the upgrade (bump tooling-api to 8.81.2, pin `withToolingApi("9.4.1")`, drop the JDK 21 launcher and `release=21`): the inline scenario passed, but the catalog scenario broke — `AddDependency` made no changes to `build.gradle.kts` when a `gradle/libs.versions.toml` was present, leaving the dependencies block absent. Likely a real behavioural change in newer `rewrite-gradle` around catalog-aware dep resolution rather than a fixture issue, since the test fixture was unchanged. Worth investigating: bisect 8.79.6 → 8.80.0 → 8.80.1 → 8.81.0 → 8.81.1 → 8.81.2 to pin the change, then either adapt the recipe or update the test expectations.
