- **0.9** (2026-05-09) — **Tier 1 of the Clean Logging plan complete; `clean-logging` v1.0 rename now justified.** Six new recipes/extensions land:
  - **`Slf4jConcatToParameterized`** — `log.info("user " + id + " did " + a)` → `log.info("user {} did {}", id, a)`. Hand-rolled rather than wrapping upstream's `org.openrewrite.java.logging.ParameterizedLogging` because upstream's `UsesMethod` precondition matches by bound method type and silently skips post-conversion calls whose LST type info is stale. Receiver detection structural (named `log`, the `@Slf4j` convention) so it composes after the `@Slf4j`-adding recipes. Reuses the existing `StringConcatDecomposer.flatten`/`formatString`/`nonLiterals` from `SystemOutVisitor` and `LogCallTemplate.escape`.
  - **`ThrowableLastArgumentNoPlaceholder`** — drops the trailing `{}` when SLF4J would otherwise consume a `Throwable` via `toString()` and silently lose the stack trace. `log.error("failed: {}", e)` → `log.error("failed", e)`. Detects the bug by counting `{}` placeholders against substitution-arg count; rewrites only when they match and the last arg is `Throwable`-assignable. Trims trailing ` `, `:`, `,` after the dropped placeholder; recognises escaped `\{}` sequences.
  - **`CommonsLoggingToSlf4j`** — Apache Commons Logging field → `@Slf4j`. Drops the field, adds the annotation, renames references, rewrites `fatal`/`isFatalEnabled` → `error`/`isErrorEnabled` (SLF4J has no fatal level), prunes Commons imports. The fatal-rename runs in a dedicated post-pass (`CommonsFatalRenameVisitor`) invoked from `convertToSlf4j` after `JavaTemplate` rebuilds the class — doing the rename in `visitMethodInvocation` worked but `JavaTemplate`'s class rebuild dropped those changes, forcing a 2-cycle convergence. Two YAML wrappers (`CommonsLoggingToSlf4jRecipe` adds Lombok deps, `…NoDeps` is multi-module gated).
  - **`JulToSlf4j` extensions** — three new patterns: lambda-supplier overloads (`logger.fine(() -> "v=" + v)`) unwrapped to body expression; `logger.isLoggable(Level.FINE)` rewritten to `log.isDebugEnabled()` for the full level table; the import-pruning generalised so any unused `java.util.logging.*` import (including `Level` after `isLoggable` rewrites) is removed alongside the `Logger` import. Block-body lambdas and bare `Supplier` references are left alone (can't safely flatten).
  - **`PrintStackTraceWithStream` was already covered** — `PrintStackTraceToLog`'s matcher is `printStackTrace(..)` so stream overloads (`System.err`, `System.out`) are caught and the stream argument is dropped. Tests `convertsPrintStackTraceWithSystemErr` and `convertsPrintStackTraceWithSystemOut` already pass. The `CLEAN_LOGGING_PLAN.md` row was stale; updated to mark already-covered. No separate recipe shipped.
  - **Shared base extraction** — `LoggerFieldToSlf4jBaseVisitor` (abstract, holds visitCompilationUnit + shouldConvert + convertToSlf4j with optional `postConvertHook`) + `LoggerFieldFinders` utility (two factory methods) + shared `LoggerField` record consolidate the near-clone field-replacement pattern previously triplicated across `DirectSlf4jLoggerFieldToLombok`, `ConvertManualLoggerToSlf4j`, and `CommonsLoggingToSlf4j`. Net: -300 lines source, +193 new files; concrete subclasses now ~20 lines each.

  `MigrateToSlf4jRecipe` YAML pipeline now ends with `Slf4jConcatToParameterized` then `ThrowableLastArgumentNoPlaceholder`, so a `Logger logger = LogManager.getLogger(...)` field with `logger.info("user " + id + " logged in")` and `logger.error("failed: {}", e)` exits as `@Slf4j` + `log.info("user {} logged in", id)` + `log.error("failed", e)` — the full pipeline proven by three integration tests (`mixedPattern_…`, `parameterisesConcatenatedSlf4jCallsAfterConversion`, `dropsTrailingThrowablePlaceholderAfterConversion`).

  Pre-release simplify pass: replaced inline JSON-style escapes with `LogCallTemplate.escape`; replaced FQN references in two visitors with normal imports; added cheap import-list early-exits in `RemoveUnusedLoggerImports.stillUsedImports` and `JulLoggerTypeDetector.referencedJulFqnsIn` so non-candidate CUs skip the full LST → string + regex / full identifier traversal. CleanCode plugin findings dropped 35 → 22 (back to the pre-Commons baseline).

  Older `openrewrite-core` versions can't run on Gradle 9 at all: 8.81.1 and earlier reject the `-b` flag — the `isGradle9OrLater` gate landed in 8.81.2, so 8.81.2 is the *first* `openrewrite-core` that runs on Gradle 9. `8.82.0-SNAPSHOT` can't be tested because only `org.openrewrite.gradle.tooling:model` is published to OSSRH snapshots, not the full `rewrite-*` set.

With K2 in place, inline scenarios work on JDK 25 + Gradle 9, but the catalog scenario still fails — confirming it's a separate bug.

  Upstream issue filed: https://github.com/openrewrite/rewrite/issues/7548. Production users on Gradle 9 are covered by the manual `SMOKE_TEST.md`.
